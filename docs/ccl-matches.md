# CCL: матчі гравців у Player Hub — драфт рішення

Статус: драфт (11.11.2026). Код написаний, тести бекенду проходять, у браузері
сторінку ще не перевіряли.

## 1. Що робимо

- Адміни турніру CCL створюють одиночні матчі між гравцями, зареєстрованими в турнірі
  (заповнені слоти `tournament_players` з `entry_stage`).
- Гравці після входу бачать **лише свої** матчі в `player-hub/tournaments?id=<CCL-id>`
  і погоджують час так само, як капітани в командних турнірах: пропозиція →
  контрпропозиція → прийняття суперником.
- Турнір з'являється в `player-hub-menu.html` і на `player-hub.html`, якщо
  в My Tournaments для нього стоїть `Player Hub visibility = Visible`. Бачать його
  адміни турніру (глобальні та `tournament_access_users.role = admin`) і гравці,
  які займають слот (`ccl_participant` з `GET /tournaments`, уже був на сервері).

## 2. Модель даних

CCL-матч = **один рядок `duels`** з `source_type = 'ccl'`, `tournament_id`, `match_id = NULL`.
Окремої таблиці немає: так само в `duels` зберігаються дуелі Challenges.

Нові колонки `duels` — загальні, не прив'язані до CCL (міграція `addColumnIfMissing` у `server.js`).
Назви збігаються з `matches`, де це можливо:

| Колонка | Опис |
| --- | --- |
| `stage` | Стадія; значення визначає турнір (CCL: `Q1`, `Q2`, `Q3`, `Main`, `Playoffs`), у БД не обмежене |
| `group_name` | Група (`group` у `matches` — зарезервоване слово, тому інша назва) |
| `round_name`, `round_order` | Тур і його порядок |
| `deadline_utc` | «Зіграти до»; пропозиція пізніше за дедлайн відхиляється |
| `proposed_time_utc` | Запропонований час |
| `proposed_time_by_player_id` | Автор пропозиції (аналог `matches.proposed_time_by_team_id`) |
| `proposed_time_status` | `pending` / `accepted` / `change_pending`, `CHECK` як у `matches` |

Для командних дуелей і Challenges колонки лишаються `NULL`. Перевірено: жоден наявний
SQL з `duels` не звертається до цих назв без префікса таблиці, тож join з `matches`
чи `standings` не стане неоднозначним.

Завдяки `duels` без змін працюють: отримання результатів з BGA (`update_matches`
бере дуель за `duel_id`, коли є `time_utc`), ігри дуелі, рейтинги, `public/player-official-duels`.

ID дуелі: `<tournament_id>-<8 символів uuid>` — стабільний, бо час на момент
створення невідомий.

## 3. Код

- `auth-server/src/duel-time-proposals.js` — **загальні** правила погодження часу дуелі
  (не залежать від турніру): пропозиція лише від гравця дуелі, лише для `Planned`,
  у майбутньому, не пізніше `deadline_utc`; прийняти може лише суперник; знімок
  `expected_proposed_*` захищає від одночасних змін (`409`).
- `auth-server/src/ccl-matches.js` — правила CCL: стадії і хто з ким може грати:
  - `Q1`/`Q2`/`Q3` — слот цієї стадії;
  - `Main` і `Playoffs` — слот `Main` або Q-слот з `league_status = qualified`.
- `auth-server/src/ccl-match-routes.js` — API.

Адмін може сам поставити час або змінити гравців: пропозиція скидається.
Зміна гравців/стадії — лише для `Planned`. Видалення — м'яке (`duels.deleted_at`).

## 4. API

| Метод | Шлях | Хто |
| --- | --- | --- |
| GET | `/ccl/:tournamentId/matches` | адмін — усі матчі + гравці для кожної стадії + формати; гравець — лише свої |
| POST | `/ccl/:tournamentId/matches` | адмін |
| PATCH | `/ccl/matches/:id` | адмін (часткове оновлення) |
| DELETE | `/ccl/matches/:id` | адмін |
| POST | `/ccl/matches/:id/time-proposal` | гравець матчу |
| PATCH | `/ccl/matches/:id/time-proposal/accept` | суперник автора пропозиції |

Зміни пишуться в `audit_trail`: `ccl.match.created/updated/deleted`, `duel.time_proposal.*`.

Часовий пояс гравця — `teams.timezone` команди його асоціації (як у Challenges);
кожен гравець у відповіді має поле `timezone`.

## 5. Інтерфейс

`player-hub/tournaments.html` — якщо турнір CCL, замість командних секцій
малюється окрема сторінка (`renderCclTournamentPage`):

- матчі згруповані «Стадія · Тур · Група»; фільтр за стадією;
- рядок: час (або «Time TBD»), гравці з прапором і аватаром, рахунок після `Done`,
  формат, дедлайн; панель активної пропозиції часу;
- гравець: *Propose time* / *Review time* / *Edit proposal* / *Change time*; модалка показує
  час в UTC і місцевий час обох гравців за поясом їхніх асоціацій;
- адмін: *Create*, *Edit*, *Delete* одиночного матчу;
- адмін, який сам грає в турнірі, перемикається між Admin mode і своїми матчами.

`player-hub-menu.html`, `player-hub.html` — `canSeeTournament` пропускає CCL-турніри
для адмінів і учасників.

## 6. Рішення та наступні кроки

Вирішено:

- Гравець бачить лише свої матчі.
- Поки створюємо лише одиночні матчі; формат обирається для кожного матчу.
- Часовий пояс — з асоціації гравця.

Наступний крок — **коригування результатів гравцем**. Зараз `POST /duels/:id/games/save`
для дуелі без `match_id` повертає 404; гравцям дозволено редагувати лише дуелі Challenges
(після `Done`/`Error`). Потрібно:

1. На сервері дозволити гравцям дуелі `source_type = 'ccl'` те саме, що для Challenges.
2. На сторінці — кнопка *Results* у своєму матчі з редактором ігор (перевикористати
   редактор дуелі з командних матчів або Challenges).

Пізніше:

- фіксований формат для стадії (напр. Q — Bo3, Playoffs — Bo5);
- масове створення пар групи і джерело груп;
- адмінське внесення результатів і неявок;
- сповіщення суперника про пропозицію;
- CCL-матчі в публічному розкладі (`public/main-page-matches`) і на сторінці турніру.
